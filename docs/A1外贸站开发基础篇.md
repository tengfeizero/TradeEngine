## 一、认知校准：外贸站不是「网站」，是「获客工具」

国内企业官网的定位是「公司门面」——建好后基本不更新，价值在于「有个地方能放公司介绍」。

海外 B2B 独立站的定位完全不同：它是一台**询盘获取机器**。衡量它成功与否的唯一业务指标是：

> **每月产生多少条有效询盘（Qualified Lead）**

不是访问量，不是停留时长，不是页面好不好看。这三点是过程指标，询盘是结果指标。

由此推导出一条对开发者极其重要的原则：

> **外贸站的所有技术与设计决策，都必须服务于一个场景**——一个德国的采购经理在 Google 搜到你的页面后，**30 秒内**判断「这家工厂靠谱，值得发一封询盘」。

这个 30 秒窗口，决定了你后面所有的架构、性能、内容、结构设计取向。理解了这一点，你就能判断客户提出的需求哪些是有效的、哪些是自我感动。

**实践含义**：

| 客户说                | 你的判断                                      |
| ------------------ | ----------------------------------------- |
| 「首页要酷炫的开场动画，5 秒那种」 | ⚠️ 危险。5 秒动画让采购经理多等 5 秒，直接伤害转化。改为轻量微动效     |
| 「要加在线支付」           | ⚠️ 要问商业模式。B2B 大宗交易极少站内支付，钱花在错的地方          |
| 「要放我们 20 年的发展历程」   | ✅ 有价值，但要压缩成 3–4 个关键节点 + 数字，不要做时间轴长文       |
| 「产品页要放 200 个参数」    | ✅ 有价值（工程客户需要），但要做可折叠的分组表格，不能平铺            |
| 「我们的优势是质量好、服务优」    | ❌ 这是废话。要帮客户翻译成可验证的证据（合格率数字、响应时效承诺、备件供应年限） |

## 二、三条获客路径的本质区别

外贸企业获取客户只有三条路，理解它们的差异才能给客户正确的组合建议。

| 渠道                                 | 本质   | 优势                               | 局限                                  | 独立站在其中的角色     |
| ---------------------------------- | ---- | -------------------------------- | ----------------------------------- | ------------- |
| **B2B 平台**<br />（阿里国际站、中国制造网、环球资源） | 租流量  | 有现成买家池、上手快、平台背书                  | 比价激烈、佣金/年费高、**客户数据不归你**、同行在同一页面直接抢客 | 承接平台客户的「信任验证」 |
| **展会**<br />（广交会、汉诺威工博会、CES）       | 买线索  | 信任建立最快、容易谈大单                     | 成本高（展位+差旅几十万起）、一年几次、不可持续            | 承接名片后的「二次验证」  |
| **独立站**                            | 自建资产 | 数据归你、可做品牌溢价、SEO 有复利、无佣金、不受平台规则约束 | 前期没有流量、需要持续内容和推广投入                  | **本体**        |

### 独立站最确定的商业价值

不要对客户过度承诺「独立站能带来大量自然流量」——那需要 6–12 个月的内容积累。独立站真正的、**当期就能兑现**的价值是：

> 买家在平台上看到你、或在展会上拿到你名片后，**回来搜索你的品牌名**。此时如果搜到的是一个比平台店铺专业十倍的官网，信任立即闭环，询盘转化率显著提升。

这是它最稳的 ROI 论证，也是你和客户沟通时最有力的说服点。自然搜索流量是第二步的复利收益。

**成熟外贸企业的标准配置**：平台（引流）+ 展会（攻坚）+ 独立站（承接与沉淀）。三者不是替代关系。

## 三、B2B 外贸站的标准信息架构

这是经过验证的骨架。偏离它可以，但要有理由。

| 页面               | 必须回答的核心问题            | 优先级                |
| ---------------- | -------------------- | ------------------ |
| **首页 Hero**      | 你是谁、做什么、凭什么信你        | P0                 |
| **产品分类页**        | 你的产品线全不全、能否覆盖我的市场    | P0                 |
| **产品详情页**        | 参数、MOQ、交期、认证、包装、报价区间 | **P0（SEO 与转化主战场）** |
| **应用场景页**        | 你的产品在我的场景里怎么用、解决什么问题 | P1                 |
| **工厂/产能页**       | 你是工厂还是贸易商、产能多大、品控怎么做 | P0                 |
| **认证资质页**        | 能否清关、能否进入我的市场        | P0                 |
| **客户案例页**        | 有没有和我类似的国家/行业客户      | P1                 |
| **服务支持页**        | 质保、备件、OEM/ODM、物流方案   | P1                 |
| **询盘页**          | 联系你有多容易、响应多快         | P0                 |
| **博客 / 技术文章**    | 长尾 SEO 流量入口          | **P1（长期最划算）**      |
| **OEM/ODM 流程页**  | 定制怎么做、起订量、打样周期       | P1                 |
| **About / 公司信息** | 公司注册信息、真实地址、真实团队     | P1                 |
| **隐私政策 / 条款**    | 合规要求（GDPR 等）         | P0（合规项）            |

### 关于「首页」的一个常见误区

很多项目把 80% 的精力放在首页，因为首页最好看、最容易给客户演示。但**首页只是导流页**，它的任务只有三个：

1. 3 秒内说清「我是谁、做什么」
2. 把访客导向正确的产品线
3. 建立第一层信任（认证、数据、客户 logo）

真正的成交发生在**产品详情页**。详情页承载了绝大部分长尾搜索流量（"40L agricultural spraying drone for rice field" 这类词的搜索意图精准、竞争小），也承载了采购决策所需的全部技术信息。

> **给客户的关键建议**：如果预算有限，优先做「10 个高质量产品详情页」，而不是「1 个特别炫的首页 + 10 个空白详情页」。

## 四、B 端买家真正在看的 8 件事

这是本篇最核心的部分。中国供应商最常犯的错误，是把 B2C 的「情绪营销」逻辑套到 B2B 上——写「专业制造商，20 年经验，质量第一，客户至上」。海外采购经理看到这类话会直接跳过，因为它不可验证。

**B2B 采购的心理模型是「风险规避」，不是「情绪激发」。** 他真正在评估的是：我会不会收不到货、会不会过不了海关、会不会被老板追责。

| # | 他关心的          | 你必须给出的具体信息                                                       | 常见错误写法                  |
| - | ------------- | ---------------------------------------------------------------- | ----------------------- |
| 1 | **认证合规**      | CE / FCC / ISO / RoHS / UN38.3 / FDA / REACH 的**证书编号 + 可下载 PDF** | 只放几个图标，没有文件；或放无效证书      |
| 2 | **你是工厂还是贸易商** | 产线照片、设备清单、厂房面积、工人数、**实拍视频**                                      | 用通用图库照片，有经验的买家一眼识破      |
| 3 | **产能与交期**     | 月产能（具体单位）、常规 Lead time（天）、旺季排产说明                                 | 写「产能充足，交期快」这类废话         |
| 4 | **MOQ 与阶梯价**  | 明确 MOQ，100 / 500 / 1000 件的价格区间                                   | 完全不提，逼买家发邮件问——大量线索就这样流失 |
| 5 | **定制能力**      | OEM 做什么、ODM 做什么、各自起订量、打样周期、打样费是否可退                               | 只写「支持定制」，买家无法判断可行性      |
| 6 | **物流与贸易条款**   | FOB / CIF / DDP 报价、20GP / 40HQ 装柜量、是否支持 LCL 拼箱、包装尺寸重量            | 完全不写，买家算不出到岸成本，直接放弃比价   |
| 7 | **付款方式**      | T/T 30% 定金 + 70% 见提单副本、L/C at sight、平台 Trade Assurance           | 不写，新买家担心资金安全            |
| 8 | **售后保障**      | 质保期、备件供应年限、海外仓位置、技术支持响应方式与时效                                     | 一句「优质售后服务」带过            |

### 为什么这 8 项比视觉设计更重要

因为这 8 项直接对应采购经理的**决策清单**。他可能同时打开 5 个供应商的网站，用 10 分钟做初筛。谁的网站能让他不用发邮件就拿到 80% 的信息，谁就进入下一轮。

**从开发角度看，这 8 项意味着什么：**

- 需要设计**结构化的产品数据模型**（不是一堆自由文本，而是可筛选、可导出的字段）
- 需要**证书文件管理**（PDF 上传、按市场归类、带有效期管理）
- 需要**阶梯价表格组件**（响应式、可横向滚动、移动端不塌）
- 需要**文件下载追踪**（谁下载了 catalog，这是高意向线索）
- 需要**多市场内容变体**（同一产品对欧盟和美国要强调不同认证）

这些是外贸站和普通企业站的技术差异点，也是你作品集里最能体现「懂行」的地方。

## 五、技术选型：三条路的取舍

| 方案                          | 典型产品                                                      | 适合场景                      | 成本参考             | 技术自由度    | SEO 天花板              | 长期维护     |
| --------------------------- | --------------------------------------------------------- | ------------------------- | ---------------- | -------- | -------------------- | -------- |
| **SaaS 建站**                 | Shopify、Ueeshop、Shopyy、Wix、Squarespace                    | 客户不懂技术、要求 2 周上线、预算有限      | 3,000–15,000 元/年 | 低（改不动结构） | 中低（URL 结构、Schema 受限） | 平台托管，省心  |
| **WordPress + WooCommerce** | 自建，插件生态                                                   | **绝大多数外贸 B2B 项目的最优解**     | 2–8 万（一次）+ 年度维护  | 中高       | 高                    | 需定期更新、防黑 |
| **定制开发**                    | Next.js / Astro + Headless CMS（Sanity / Strapi / Payload） | 品牌要求高、多语言多市场、需要对接 ERP/CRM | 10 万+            | 极高       | 极高                   | 需专职团队    |

### 为什么第一次做建议选 WordPress

不是因为它先进，而是因为**它的问题都有解**。外贸站需要的每一项能力，WordPress 生态里都有成熟方案：

| 需求             | 主流方案                                             |
| -------------- | ------------------------------------------------ |
| 产品目录 / 询盘（非支付） | WooCommerce（关闭购物车，只做 Catalog 模式）或 CPT + ACF      |
| 多语言            | WPML（商业）/ Polylang（免费）/ TranslatePress           |
| SEO            | Yoast SEO / Rank Math（含 Schema、sitemap、面包屑）      |
| 询盘表单           | WPForms / Gravity Forms / Fluent Forms           |
| 缓存与加速          | WP Rocket / LiteSpeed Cache + Redis Object Cache |
| 安全             | Wordfence / Solid Security + Cloudflare WAF      |
| 备份             | UpdraftPlus / BlogVault                          |
| 图片优化           | ShortPixel / Imagify（WebP/AVIF 自动转换）             |

**出问题时全世界都有教程**——这是外包项目最实际的考量，因为客户最终要自己维护，或者要交给下一个开发者。

### 什么时候必须上定制开发

出现以下任意两条，WordPress 就该退场：

- 需要对接客户的 ERP / CRM / PIM（产品数据在别处维护，要自动同步）
- 目标市场 ≥ 5 个，每个市场有独立的价格体系、认证要求、语言
- 需要 ISR / SSG 级别的首屏性能（LCP < 1.5s 硬指标）
- 有复杂的 3D 产品展示、配置器（configurator）
- 需要多站点架构（每个国家独立域名 + 独立库存）

### ⚠️ 一条硬性基础设施要求

> **服务器必须放在海外**（美国 / 欧洲 / 新加坡），并套 Cloudflare CDN。

用国内主机，欧洲客户打开需要 8 秒以上，移动端更糟。这个细节会让整个项目前功尽弃，而很多国内开发者会忽略。

**选型对照（务实建议）**：

| 客户市场  | 主机位置建议                   |
| ----- | ------------------------ |
| 欧美为主  | 美国东部 / 德国法兰克福            |
| 东南亚为主 | 新加坡                      |
| 中东为主  | 阿联酋 / 德国                 |
| 全球分散  | Cloudflare 全站 + 单点源站（美东） |

## 六、上线前必须处理的基础项

这一节是「交付质量」的分水岭。漏了任何一项，都可能在客户上线后被投诉。

### 6.1 基础与合规

| 项目              | 要求                  | 技术实现要点                                                                 |
| --------------- | ------------------- | ---------------------------------------------------------------------- |
| **域名**          | .com 优先，短、好念、避开拼音歧义 | 检查历史（是否被墙、是否曾有垃圾内容）、避免连字符、避免与知名品牌近似                                    |
| **SSL / HTTPS** | 强制全站 HTTPS          | Let's Encrypt 自动续期 + HSTS + 301 重定向                                    |
| **多语言**         | 英语必做；按市场加西/阿/俄/法/德  | 子目录（`/es/`）优于子域名；**必须配 hreflang**（含 x-default）；**不要用机器翻译直接上**，痕迹重会反伤信任 |
| **移动端**         | 移动优先                | 新兴市场（东南亚 / 中东 / 南美）70%+ 流量来自手机；触摸目标 ≥ 44px；表单键盘类型正确                    |
| **Cookie 同意**   | 欧盟流量必须有             | CMP 工具（CookieYes / Complianz），必须**阻断式**（先同意再加载 GA）                     |
| **隐私政策 / 条款**   | GDPR 要求             | 明确数据用途、保留期限、数据主体权利、DPO 联系方式                                            |
| **无障碍**         | a11y 基础             | 图片 alt、语义化标签、对比度 ≥ 4.5:1、键盘可达                                          |

### 6.2 性能（这是技术人员最能拉开差距的地方）

| 指标                | 目标              | 实现手段                                           |
| ----------------- | --------------- | ---------------------------------------------- |
| **LCP**（最大内容绘制）   | < 2.5s（移动端）     | Hero 图预加载、AVIF/WebP、CDN、避免 CSS 阻塞              |
| **CLS**（累积布局偏移）   | < 0.1           | 图片/iframe 预设宽高、字体 `font-display: swap` + 字体预加载 |
| **INP**（交互延迟）     | < 200ms         | 减少主线程长任务、延迟加载非关键 JS                            |
| **PageSpeed 移动分** | ≥ 70（务实目标 ≥ 80） | 图片压缩、JS 拆分、critical CSS 内联                     |
| **TTFB**          | < 600ms         | 页面缓存、对象缓存（Redis）、OPcache                       |
| **首屏资源总量**        | < 1MB           | 图片懒加载、字体子集化（只保留拉丁字符集）                          |

**技术清单：**

```text
□ 图片：AVIF（优先）/ WebP 自动转换 + srcset 响应式 + loading="lazy"（Hero 图除外，用 fetchpriority="high"）
□ 字体：自托管 + 子集化 + preload 关键字体 + font-display: swap
□ JS：defer / async、按需加载、第三方脚本（GA、客服插件）延后到交互后
□ CSS：critical CSS 内联、非关键样式异步加载
□ 缓存：页面缓存 + 对象缓存 + 浏览器缓存（静态资源 Cache-Control: max-age=31536000, immutable）
□ CDN：Cloudflare（开 Brotli、Early Hints、Tiered Cache）
□ 数据库：索引优化、避免 N+1 查询（产品列表页尤其注意）
```

### 6.3 询盘链路（最容易出事故的环节）

> **询盘收不到，等于整个项目失败。** 这是交付后最常见的投诉，务必当作 P0 处理。

| 环节        | 风险          | 处理方案                                                                                                      |
| --------- | ----------- | --------------------------------------------------------------------------------------------------------- |
| **邮件送达率** | 询盘进了垃圾箱     | **必须配 SPF + DKIM + DMARC**（很多人只配 SPF）；用专业 SMTP（SendGrid / Mailgun / Amazon SES / 腾讯企业邮），不要用服务器本地 sendmail |
| **垃圾询盘**  | 一天几十条 spam  | reCAPTCHA v3（无感）+ honeypot 隐藏字段 + 时间戳校验 + Akismet；表单限流                                                    |
| **实时通知**  | 客户 48 小时才看到 | 邮件 + 企业微信/钉钉机器人 + WhatsApp Business API 三通道；响应时效 SLA 写进合同                                                 |
| **数据落库**  | 邮件丢了就没了     | 表单数据必须写入数据库/CRM，不能只依赖邮件                                                                                   |
| **自动回复**  | 无           | 提交后立即发确认邮件（含报价流程说明），提升信任                                                                                  |
| **转化追踪**  | 无法衡量效果      | GA4 `generate_lead` 事件 + Google Ads 转化 + 表单来源 UTM 记录                                                      |

**一个专业细节**：在询盘表单里加一个隐藏字段记录**来源页面**和 **UTM 参数**。这样客户问「询盘从哪来的」你能回答，也是你证明自己工作价值的证据。

### 6.4 SEO 与技术基础

| 项目              | 要点                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| **TDK**         | 每个页面独立 Title / Description；Title 含核心词 + 卖点，控制在 60 字符内                                                  |
| **URL 结构**      | 语义化、短、全小写、连字符分隔；`/products/agricultural-spraying-drone/`                                               |
| **结构化数据**       | `Organization`、`Product`（含 `offers`、`aggregateRating` 谨慎使用）、`BreadcrumbList`、`FAQPage`、`LocalBusiness` |
| **sitemap.xml** | 自动生成、分产品/文章两套、提交 Search Console                                                                        |
| **robots.txt**  | 不要误屏蔽 CSS/JS；屏蔽后台、搜索结果页、参数页                                                                            |
| **canonical**   | 分页、筛选参数页必须处理，否则重复内容                                                                                    |
| **404 / 301**   | 老站迁移必须做全量 301 映射表，别让客户丢历史权重                                                                            |
| **图片 SEO**      | 文件名语义化（`40l-agricultural-spraying-drone.jpg`），alt 描述性                                                  |
| **面包屑**         | 有导航价值 + 结构化数据加成                                                                                        |
| **埋点**          | GA4 + Google Search Console + Bing Webmaster                                                           |

### 6.5 安全与运维

```text
□ WAF（Cloudflare）+ 登录限流 + 2FA
□ 定期备份（每日数据库 + 每周全站），备份文件异地存储，且**必须做过恢复演练**
□ 自动更新策略：核心版本手动、插件小版本自动、更新前快照
□ 文件权限（755 目录 / 644 文件）、禁用文件编辑、隐藏版本号
□ 监控：Uptime（UptimeRobot/BetterStack）+ 错误日志 + 性能监控（Core Web Vitals）
□ 证书到期提醒（自动化续期 + 二次告警）
□ 变更日志：每次改动留记录，客户问「上周改了什么」能答
```

## 七、流量从哪来

这是独立站最难的部分，也是最容易被客户低估的部分。**建站只是入场券，流量才是成本大头。**

| 方式             | 见效周期      | 成本量级           | 说明                                                               |
| -------------- | --------- | -------------- | ---------------------------------------------------------------- |
| **SEO 自然流量**   | 6–12 个月   | 低（但要持续内容投入）    | 长尾词布局：「industrial inspection drone for power line + 国家名」竞争小、意图精准 |
| **Google Ads** | 立刻（1–2 周） | 高（B2B 点击 $2–8） | 适合验证关键词与落地页转化率；先跑小预算测词                                           |
| **LinkedIn**   | 1–3 个月    | 中              | B2B 最对口：内容运营 + Sales Navigator 主动触达采购                            |
| **平台导流**       | 立刻        | 低              | 阿里国际站店铺内放官网链接（注意平台规则）                                            |
| **邮件开发（EDM）**  | 持续        | 低              | 配合官网做信任背书，回复率明显提升                                                |
| **行业目录 / 黄页**  | 慢         | 低              | 外链建设的一部分（Europages、Kompass 等）                                    |
| **YouTube**    | 3–6 个月    | 中              | 工厂实拍、产品作业视频，B2B 转化效果极好且被严重低估                                     |

### 内容营销：最划算的长期投入

每篇技术文章都能持续吃到长尾搜索流量，而且优质内容会被行业站转载，带来自然外链。B2B 外贸站的内容选题方向：

- **选型指南**：「如何为 40℃ 高温环境选择植保无人机电池」
- **对比测评**：「RTK vs 普通 GPS：测绘精度差多少，成本差多少」
- **合规解读**：「2026 年欧盟无人机出口 CE 认证最新要求」
- **应用案例**：「某巴西电力公司如何用无人机降低 60% 巡检成本」
- **故障排查**：「植保无人机常见 5 种喷嘴堵塞原因及处理」

这类内容的搜索意图极其精准，来的是真正在看技术方案的采购/工程师，不是闲逛流量。

**给客户的关键提醒**：第一年预算建议按 **「建站 : 推广 = 1 : 1」** 配置。很多人建完站不投推广，半年后说「独立站没用」——这是最常见的失败模式，也是你作为专业顾问应该提前警告的。

## 九、五个最常见的坑

### 坑 1：文案写成「专业制造商，20 年经验，质量第一」

海外买家看到这种话直接跳过，等于没说。**要给数字、给证据、给可验证的承诺**。

| ❌ 无效表达    | ✅ 有效表达                                              |
| --------- | --------------------------------------------------- |
| 质量第一，客户至上 | 出货前 100% 全检，批次不合格率 0.3%（附检测报告样本）                    |
| 产能充足，交期快  | 月产能 50,000 台，常规订单 25 天出货，旺季 35 天                    |
| 优质售后服务    | 24 个月质保，5 年备件供应，技术问题 12 小时内响应                       |
| 支持定制      | OEM 起订 100 台（改 logo + 包装），ODM 起订 500 台（改结构），打样 15 天 |

### 坑 2：用中国风审美做欧美 B2B 市场

红金配色、水墨、祥云、龙纹——在欧美 B2B 语境里显得不专业甚至廉价。

**例外**：文化本身就是卖点的品类（茶叶、瓷器、丝绸、香道），东方美学是加分项。**判断标准：文化是产品价值的一部分，还是产品的包装？**

### 坑 3：图片全靠图库或盗图

B 端买家会以图搜图。发现是图库图，信任归零；发现盗用同行图，直接出局，还有法律风险（DMCA 投诉、索赔）。

**正确做法**：工厂实拍 + 产品白底图 + 应用场景实拍。手机拍的实景，胜过精修的图库图。

### 坑 4：询盘表单字段太多

**每增加一个必填字段，转化率下降约 10%。** 超过 10 个字段，转化断崖式下跌。

**最优字段组合（5–6 个）**：

- 姓名、公司、邮箱、国家
- 需求描述（自由文本，比下拉框更能看出意向质量）
- 可选：WhatsApp、采购量区间

**把「公司规模」「年采购额」「预算」这类敏感字段放到第二步**，或交给业务在邮件里问。

### 坑 5：只留一个 info@ 邮箱，48 小时才回

B2B 采购通常同时在谈 3–5 家供应商。谁先回，谁拿到订单的概率就高一大截。

**必须做到**：

- WhatsApp 一键联系（欧美/中东/南美采购主流沟通方式）
- 询盘 12 小时内响应（写进官网承诺，形成差异化）
- 表单提交后立即自动回复（告知「已收到，24 小时内给方案」）
- 设一个「响应时效」的展示位，这是可量化的信任资产

## 附录 A：外贸术语速查表

技术人员最大的劣势是不懂业务黑话。客户说「给他做个 FOB 报价页」，你得知道在说什么。

### 交易与价格

| 术语              | 全称                          | 含义                         |
| --------------- | --------------------------- | -------------------------- |
| **MOQ**         | Minimum Order Quantity      | 最小起订量，最常见的第一个问题            |
| **FOB**         | Free On Board               | 离岸价。卖方负责送到装运港并装船，之后风险转移给买方 |
| **CIF**         | Cost, Insurance and Freight | 到岸价（含保险运费）。卖方付运费到目的港       |
| **CFR**         | Cost and Freight            | 成本加运费（不含保险）                |
| **EXW**         | Ex Works                    | 工厂交货价。买方承担全部运输，卖方责任最小      |
| **DDP**         | Delivered Duty Paid         | 完税后交货。卖方承担全部费用与关税，买方最省心    |
| **LCL / FCL**   | Less/Full Container Load    | 拼箱 / 整柜                    |
| **20GP / 40HQ** | 20尺普柜 / 40尺高柜               | 标准集装箱规格，装柜量是买家必问数据         |
| **HS Code**     | Harmonized System Code      | 海关商品编码，决定关税税率和监管条件         |
| **Lead Time**   | —                           | 从下单到发货的周期                  |

### 付款与单证

| 术语                  | 含义                                    |
| ------------------- | ------------------------------------- |
| **T/T**             | 电汇。常见条款「30% 定金 + 70% 见提单副本」           |
| **L/C**             | 信用证。银行担保付款，大额订单常用，单证要求严格              |
| **D/P、D/A**         | 付款交单 / 承兑交单，风险高于 L/C                  |
| **PI**              | Proforma Invoice，形式发票。报价确认后出具，等同订单确认书 |
| **CI**              | Commercial Invoice，商业发票。清关必备          |
| **B/L**             | Bill of Lading，提单。物权凭证                |
| **Trade Assurance** | 阿里平台的担保交易，新买家常用                       |

### 认证与合规

| 术语                    | 适用   | 含义                   |
| --------------------- | ---- | -------------------- |
| **CE**                | 欧盟   | 强制性安全认证，产品进入 EU 的通行证 |
| **FCC**               | 美国   | 无线电/电磁兼容认证           |
| **RoHS**              | 欧盟   | 限制有害物质（铅、汞、镉等）       |
| **REACH**             | 欧盟   | 化学品注册评估授权限制法规        |
| **UN38.3**            | 全球   | 锂电池运输安全测试，含电池产品必做    |
| **ISO 9001**          | 全球   | 质量管理体系认证             |
| **ISO 14001**         | 全球   | 环境管理体系认证             |
| **HACCP / ISO 22000** | 食品   | 食品安全管理体系             |
| **FDA**               | 美国   | 食品/药品/医疗器械注册         |
| **BSCI / Sedex**      | 社会责任 | 欧美买家（尤其零售品牌）常要求      |
| **MSDS / SDS**        | 化学品  | 材料安全数据表              |

### 角色与场景

| 术语                      | 含义                                      |
| ----------------------- | --------------------------------------- |
| **OEM**                 | 代工贴牌。客户提供品牌，工厂生产                        |
| **ODM**                 | 设计代工。工厂提供设计+生产，客户贴牌                     |
| **SKU**                 | 库存单位，一个规格 = 一个 SKU                      |
| **PIM**                 | 产品信息管理系统，多市场运营必备                        |
| **RFQ**                 | Request for Quotation，询价请求              |
| **Distributor / Agent** | 经销商 / 代理商（独立站高频目标客户）                    |
| **BVLOS**               | Beyond Visual Line of Sight（无人机领域）超视距飞行 |

## 附录 B：上线前自查清单

> 交付前逐项打勾。这份清单本身就是你专业度的体现——可以做成交付文档的一部分。

### 内容完整性

```text
□ 公司真实信息：注册名、地址（含 Google 地图）、电话、邮箱
□ 工厂实拍：外景、产线、设备、实验室、仓库、团队
□ 产品资料：型号、参数表、应用图、包装尺寸重量
□ 认证证书：PDF 原件可下载（带编号和有效期）
□ 案例：至少 3 个，含国家、行业、用量、成效
□ 服务条款：MOQ、Lead time、付款方式、质保、备件
□ 英文文案：母语者审校，无中式英语、无机器翻译痕迹
```

### 技术检查

```text
□ HTTPS 全站强制，无混合内容警告
□ 移动端全流程可用（表单能提交、表格能横滑、菜单能展开）
□ PageSpeed 移动端 ≥ 70，LCP < 2.5s
□ 所有图片有 alt，所有表单有 label
□ TDK 全部填写，无重复 title
□ sitemap.xml 可访问，已提交 Search Console
□ robots.txt 不误屏蔽资源
□ 结构化数据通过 Rich Results Test
□ 404 页面友好，301 映射表完整
□ 多语言 hreflang 正确（含 x-default）
```

### 询盘链路（逐项实测，不要假设）

```text
□ 表单提交后：数据库有记录 ✅ / 邮件到达收件箱（非垃圾箱）✅ / 自动回复已发 ✅
□ SPF、DKIM、DMARC 三项全部配置并验证通过
□ reCAPTCHA 生效，且不误杀正常用户
□ WhatsApp / 在线客服可用，移动端可唤起
□ GA4 能看到 generate_lead 事件
□ 隐藏字段能记录来源页和 UTM
□ 用真实手机网络（4G）测试一遍完整提交流程
```

### 运维交接

```text
□ 交付后台账号 + 操作手册（图文）
□ 备份策略已配置并**做过一次恢复演练**
□ 监控已接入（Uptime + 错误日志）
□ 证书自动续期已配置
□ 变更日志开始记录
□ 交付一份「常见问题处理指南」给客户对接人
```

## 附录 C：技术能力如何转化为可信案例

你提到需要案例来证明「懂外贸站开发维护」。纯粹的视觉稿（好看的设计图）说服力有限，因为客户会想「好看不等于能收询盘」。建议按以下维度构建作品集：

| 作品集要素        | 展示什么                                 | 为什么打动人            |
| ------------ | ------------------------------------ | ----------------- |
| **完整站（可访问）** | 真实域名，能点、能提交表单                        | 证明端到端交付能力         |
| **性能报告截图**   | 改造前后的 PageSpeed / Core Web Vitals 对比 | 技术硬指标，最有说服力       |
| **询盘链路演示**   | 提交表单 → 收到邮件 → CRM 记录 → GA4 事件        | 证明你懂业务闭环，不只是画页面   |
| **多语言实现**    | hreflang 结构、翻译工作流                    | 区分普通建站与外贸建站       |
| **SEO 技术清单** | Schema、sitemap、canonical 策略          | 证明懂搜索             |
| **维护月报样本**   | 一份假的「月度维护报告」（更新记录、安全事件、性能趋势、询盘统计）    | **极少有人做，最容易脱颖而出** |
| **行业文档**     | 就是你正在写的这份系列                          | 证明你懂业务语言，能跟客户对话   |

### 三个最容易加分的具体动作

1. **做一份「询盘链路压力测试报告」**：模拟 100 条并发提交，证明表单不丢单。这个几乎没人做。
2. **做一份「性能优化前后对比」**：拿一个真实站点（或自己搭的样板站），把移动端分数从 40 优化到 90，记录每一步做了什么、收益多少。
3. **做一份「外贸站技术审计清单」**：把附录 B 做成一个评分表，客户填完就知道自己站点的问题在哪。这是天然的获客工具，也是你专业形象的载体。
