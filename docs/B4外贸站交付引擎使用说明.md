## 一、五分钟上手

```bash
# 1) 建站骨架（品牌名 + 布局变体）
engine new clients/demo --brand "Demo Foods" --theme editorial

# 2) 本地预览（监听内容变化，自动重建）
cd clients/demo && engine dev            # 默认 :8080

# 3) 生产构建
engine build                             # 产物在 .build/public
engine validate                          # 只校验内容，不构建

# 4) 起服务（静态站 + 询盘 API）
engine serve -addr :8080
```

**一个站 = 一个目录。** 加客户 = 加目录 + `git init`，不需要建库、不用跑 migration。

## 二、安装与构建引擎

**用发布包（推荐）**：从 releases 取对应平台压缩包，解压即用，单文件无依赖。

**从源码构建**：

```bash
export PATH="/path/to/go/bin:$PATH"
export GOCACHE=/path/to/cache GOPATH=/path/to/gopath
export GOPROXY=https://goproxy.cn,direct GOSUMDB=off

cd engine
go build -o /tmp/engine.exe ./cmd/engine      # Windows
go build -o /tmp/engine ./cmd/engine          # macOS / Linux
go test ./...                                  # 100 个测试函数
```

**交叉编译四平台**：`bash scripts/release.sh`（产物带 `_<goos>_<goarch>` 后缀，内含 engine + README + LICENSE）。

## 四、CLI 速查（14 命令）

| 命令 | 用途 | 常用参数 |
| --- | --- | --- |
| `engine new <dir>` | 建站骨架 | `--brand` `--skin <名>`（旧 `--theme` 仍可用） |
| `engine skins [dir]` | 列出可用皮肤（0.10.0） | 无 |
| `engine dev [dir]` | 监听变化自动重建 + 预览 | `--addr :8080` `--trust-proxy` |
| `engine build [dir]` | 构建静态站 | `--db <path>` 从内容库读；`--skin <名>` 临时换皮预览 |
| `engine validate [dir]` | 只校验 | `--db <path>` |
| `engine serve [dir]` | 静态站 + 询盘 API | `--addr :8080` `--trust-proxy` |
| `engine inquiries [dir]` | 查看已收询盘 | `--status` `--days` `--limit` `--json` |
| `engine digest [dir]` | 未读询盘汇总发信 | `--cron`（每日 09:00 常驻）`--at HH:MM` `--hours` `--dry-run` |
| `engine doctor [dir]` | 结构体检 + 旧字段迁移 | `--fix`（先备份再改写） |
| `engine admin [dir]` | 本地内容后台（改文件） | `--addr 127.0.0.1:9090` |
| `engine studio [dir]` | 表单化编辑（改库，多用户 + 审核流） | `--addr 127.0.0.1:9190 --db .data/content.db` |
| `engine import [dir]` | 文件 → 内容库（单向闸） | `--db` `--force` |
| `engine export [dir] --out <dir>` | 内容库 → 可构建骨架 | `--force` |
| `engine deploy [dir] --to <dir>` | 产物同步到目标目录 | `--manifest` `--dry-run` |
| `engine version` | 版本 | — |

**典型组合**：

```bash
# 交付期日常
engine dev                      # 边改边看
engine validate && engine build  # 改完先校验

# 客户要自助改内容
engine import --db .data/content.db     # 文件入库（一次性闸门）
engine studio --db .data/content.db     # 客户在库里改
engine build --db .data/content.db      # 库内容构建
engine export --out clients/x-restored  # 需要时把库内容拿回文件

# 上线
engine build && engine deploy --to /srv/www/x --manifest
```

> **`deploy --to` 只支持本机路径。** 远程用 `rsync --delete`（`docs/deploy.md` 有 systemd + nginx 样例），Cloudflare Pages 用 `wrangler pages deploy .build/public`。

> **反代之后必须加 `--trust-proxy`。** 不加的话 `serve` 只认 `RemoteAddr`，所有询盘都顶着 Nginx/Cloudflare 的 IP：限流会把整站客户当成同一个人，第 11 个真实客户就吃 429。正确姿势是 `engine serve --addr 127.0.0.1:8080 --trust-proxy`，并且**只在确实有反代时打开**——没有反代却开着它，任何人都能伪造 `X-Forwarded-For` 绕过限流。

## 五、写内容（最容易踩坑的一章）

### 5.1 四条硬规则（每条都对应一次真实事故）

```yaml
# ① i18n 一律块式，禁止流式
title:
  en: Chili Crisp 210 g
  zh: 油泼辣子 210 g
# ❌ title: { en: Chili Crisp, 210 g, zh: … } —— 合法 YAML，静默截断到第一个逗号

# ② 值里禁止半角冒号+空格（": "）
summary:
  en: The spec that matters — 18% solids     # ✅ 用破折号
# ❌ en: The spec that matters: 18% solids

# ③ 主题字体值不要带内部引号，或整体加引号
fonts:
  body: "Helvetica Neue, Helvetica, Arial, sans-serif"

# ④ 列表项里 en/zh 同级同缩进
highlights:
  - en: Batch SHU printed on every label
    zh: 每批实测辣度印在标签上
```

> 上面每一处多语言值都是**块式**。原模板为了省行数写成 `title: {en: …, zh: …}`，读者照抄就会踩 5.1 的坑①——示例代码是会被复制的，它必须和规范一致。

### 5.3 字段速查与限制

| 字段 | 规则 |
| --- | --- |
| `moq_unit` | 仅 `kg` / `pcs` / `set` / `ton` |
| `hs_code` | 6–10 位数字字符串；可留空但强烈不建议 |
| `specs[].filterable` | 为 true 时必须有 `value_num` |
| 数值参数 | 必须带 `unit` |
| `certificate.expires` | 90 天内到期会告警；已过期前台不展示 |
| `seo.title` | 30–60 字符（超长告警）；SEO description 100–160 |
| `case.result` | 必须含数字，否则告警 |
| 媒体引用 | 写 `media/...png`，**不要写 webp 作引用主体**（读不出宽度 → `0w` srcset → 图不加载） |

### 5.4 区块

**20 种**：`hero` `richtext` `image_text` `stats` `features` `product_grid` `category_grid` `scenario_grid` `certificate_grid` `case_grid` `process` `team` `faq` `cta` `logos` `gallery` `factory` `testimonials` `legal_facts` `inquiry`。

**写错 type 整块内容会静默消失**，但构建会失败（白名单校验）。后三种（`factory` / `testimonials` / `legal_facts`）是 0.13.0 新增的证据与合规类区块，用法见 5.5。

v0.9.0 起的三件通用增强（所有区块都认）：

```yaml
kicker:            # 章节眉题：section 标题上方的小标签（Product Lines / Core Technology…）
  en: Use Cases
  zh: 应用场景
```

**`features`（v0.9.0 新增）**——能力/卖点网格，两种风格：

```yaml
- type: features
  style: icon            # icon（默认）= 图标卡；numbered = 「01 / 标签」编号卡
  items:
    - icon: cpu          # 图标名必须在内置白名单里，拼错报 ICON_UNKNOWN
      title: { en: Flight control, zh: 飞控 }
      body:  { en: Dual IMU on separate rails., zh: 双 IMU 独立供电。 }
      checks:            # 可选：勾选清单（numbered 风格同样可用）
        - { en: Cross-checked every cycle, zh: 每周期交叉比对 }
- type: features
  style: numbered        # 自动编号 01、02…；tag 是编号后的小标签
  items:
    - tag: { en: Flight Control, zh: 飞控 }
      title: { en: AeroNova FC System, zh: 自研飞控系统 }
      body:  { … }
```

**图标**：`engine new` 出的站不用管，直接引用名字即可。可用名单见 `internal/icons/icons.go`（`camera` `leaf` `cpu` `shield` `globe` `truck` `package` `headset` `award` `check` `bike` `cup` `sprout` `recycle` …共 40 个），统一 24×24 描边风、跟随文字颜色、按页打包成 sprite。`scenarios[].icon` 命中后场景卡走图标卡（不再显示封面图）；不配 icon 场景卡仍用 `cover`。

**`image_text.checks`**：勾选清单形态（对应设计稿工厂能力清单），`bullets` 仍是普通圆点列表。

### 5.5 证据类区块与法定披露（0.13.0）

这三块解决同一个问题：**B 端买家判断「能不能信你」，靠的是可核验的锚点，不是形容词**。所以引擎在渲染之外还加了两条**错误级**校验——锚点缺失直接构建失败，而不是留一个空白区块在线上。

#### `factory`（工厂证据链）

```yaml
- type: factory
  kicker: { en: Factory, zh: 工厂 }
  title:  { en: Inside the factory, zh: 走进车间 }
  capacity:                          # 产能条（value 必填，缺了不渲染）
    - { item: { en: Annual capacity, zh: 年产能 }, value: 120,000 units, note: { en: 2 lines, zh: 两条线 } }
  equipment:                         # 设备清单（买家就看型号与台数）
    - { name: { en: CNC tube cutting line, zh: 数控切管机 }, qty: 4, note: { en: ±0.1 mm, zh: 精度 ±0.1mm } }
  qc:                                # 质检工序（序号自动）
    - { title: { en: Incoming inspection, zh: 来料检验 }, body: { en: …, zh: … } }
  audits:                            # 第三方审核：name 一旦填，number 与 date 必填
    - name:   { en: BSCI social audit, zh: BSCI 社会责任审核 }
      number: BSCI-26-88421
      issuer: TÜV Rheinland          # 纯字符串，不用写 { en: … }
      date:   '2026-03-11'
      valid_until: '2027-03-10'
      file:   media/certs/bsci-26.pdf
  retention: { en: Every lot keeps two reference frames for five years., zh: 每批留两个基准车架，保存五年。 }
  photos:                            # 车间照：带拍摄日期，旧照一眼看得出
    - { src: media/factory/line-1.jpg, caption: { en: Line 1, zh: 一号线 }, date: '2026-08' }
```

**校验**：`audits[]` 里只要填了 `name`，`number` 和 `date` 缺一即报 **`FACTORY_AUDIT_INCOMPLETE`（错误）**。理由很直接：没有编号的「已通过 XX 审核」买家查不到，等于没写。

#### `testimonials`（客户证言）

```yaml
- type: testimonials
  title: { en: What buyers say, zh: 客户怎么说 }
  items:
    - quote:   { en: Third season on the same frames, no failures., zh: 同批车架用到第三季，没有失效。 }
      author:  Jonas Berg
      role:    { en: Head of Product, zh: 产品负责人 }
      company: Nordvelo AB
      country: SE
      date: '2026-05'
      product: g500-gravel           # 产品 slug：自动生成回流链接
```

**校验**：有 `quote` 就必须有 `author` 与 `company`，否则报 **`TESTIMONIAL_INCOMPLETE`（错误）**。不署名的好评在 B 端等于自说自话。

#### `legal_facts`（法定披露）

区块本身只给标题，**数据全部来自 `settings.yaml` 的 `compliance`**——一处真相，不在正文里抄第二份：

```yaml
# settings.yaml
compliance:
  eu_responsible:                    # EU GPSR（2024/12 起强制）
    name: Ridgeway Europe B.V.
    address: Keizersgracht 1, 1015 Amsterdam, NL
    email: eu@ridgeway.example.com
    phone: '+31 20 123 4567'
  legal_notice:                      # 德国 Impressum
    register_no: KvK 87654321
    register_court: Amsterdam
    vat_id: NL864123456B01
    managing_director: M. de Vries
    email: legal@ridgeway.example.com
  epr:                               # 包装法 / 电子废弃物
    de_packaging: LUCID DE1234567890123
    fr_packaging: FR234567_01
    weee: DE12345678
```

```yaml
# content/pages/legal-notice.yaml
- type: legal_facts
  title: { en: Company details, zh: 公司信息 }
```

**三处出口，位置不同用途不同**：

| 位置 | 内容 | 为什么在这 |
|---|---|---|
| 产品页（自动，无需配置区块） | 制造商 + 欧盟责任方 | GPSR 要求「在线商品页」明示 |
| 全站页脚（自动） | 欧盟责任方一行 | GPSR：任何面向欧盟买家的页面都可查 |
| `legal-notice` 页的 `legal_facts` | 注册号 / 注册法院 / VAT / 法人 / EPR | 德国 Impressum 与包装法要求 |

**告警（不是错误，因为引擎无法断定你到底在哪些国家卖）**：

- `markets` 命中 EU / EEA / UK / GB 或任一欧盟成员国 → 没配 `eu_responsible` 报 `GPSR_RESPONSIBLE_MISSING`
- `markets` 命中 DE → 没配 `epr.de_packaging` 报 `EPR_MISSING`
- 没有已发布的 `legal-notice` / `business-terms` 页 → 报 `LEGAL_NOTICE_MISSING` / `BUSINESS_TERMS_MISSING`

> **没配就不输出，绝不编造**。宁可缺一项被 B2 记 P0，也不在线上印一个假的责任方——后者是法律风险，前者只是分数。

## 六、主题定制

```yaml
# theme/theme.yaml
colors:
  primary: "#8C2F1B"       # 结构色：导航、链接
  primary-fill: "#8C2F1B"  # 暗色主题才需要单独给（按钮填充）——连字符，不是下划线
  ink: "#2B211B"
  paper: "#FAF5EC"
  accent: "#9A5B21"        # 强调色：kicker、编号 → 必须 ≥4.5:1
fonts:
  heading: "Iowan Old Style, Georgia, serif"
  body: "Helvetica Neue, Arial, sans-serif"
radius: 2px
skin: editorial            # 换这行 = 整站换一套设计，内容一字不动
```

- **色键只有 8 个、字体键 3 个**：`primary` `primary-fill` `secondary` `ink` `paper` `surface` `muted` `accent` / `heading` `body` `mono`。写别的键（比如 `primary_fill`）v0.8.2 起直接构建失败（`THEME_UNKNOWN_TOKEN`）——在 0.8.1 及以前它会静默无效。`secondary` 只给渐变/标题强调用，不写跟随 `primary`；`mono` 给编号与代码片段。
- **只改 token，不改模板结构**——改了结构复用率归零，且下次升级会冲突。
- `accent` 用来做小字时，先算对比度（`#A87C3F` 在暖纸底上只有 3.28:1，会被 Lighthouse 抓）。
- `tech` 暗色皮肤必须单独给 `primary-fill`，否则「按钮白字」与「正文亮字」二选一。

### 6.1 皮肤：同一份内容，换一套设计（0.10.0）

皮肤的分工是「配色归 colors，设计归 skin」：`colors` 决定品牌色，`skin` 决定版式语法、边框圆角、字阶、首屏构图——全部观感。换肤不动内容、不动结构、不动表单。

```bash
engine skins                        # 列出全部皮肤（内置 7 套 + 站点自定义），按行业分组
engine build clients/x --skin industrial   # 临时换皮预览，不改 theme.yaml（比稿用）
```

内置七套，按行业挑：

| 皮肤 | 一句话 | 适用 |
| --- | --- | --- |
| `classic` | 中性商务基线 | 通用制造，不确定时先用它 |
| `editorial` | 杂志排版：粗顶线、衬线大标题、无卡片边框 | 茶叶/文创/轻奢 |
| `tech` | 暗色仪表盘：辉光、渐变、方角 | 无人机/3C/智能硬件 |
| `industrial` | 工程图纸：深色页头条、2px 实线、等宽编号、无阴影 | 机械/五金/化工/建材 |
| `organic` | 有机自然：暖纸、大圆角、柔影、居中版式 | 食品/农产品/手作 |
| `minimal` | 画廊留白：无边框、发丝线、大间距 | 家居/设计品/高端配件 |
| `ecobike` | 生态骑行：深林绿暗色门厅、白卡细线、薄荷绿点缀、全站居中 | 自行车/户外出行/环保制造 |

**自定义皮肤**：把 CSS 放进 `<site>/skins/<名字>.css`，头部注明元信息即可，不用重编译：

```css
/*!
 * @skin my-brand
 * @label 客户品牌版
 * @category 站点自定义
 * @tone light
 */
html[data-skin=my-brand] .site-header{ ... }
```

规则：① 每条选择器带 `html[data-skin=名字]` 前缀（测试会拦）；② 末尾自带 `@media (max-width:900px)` 重压列数；③ 只覆写你关心的部分，其余落到中性基线；④ 文件名即皮肤名，同名覆盖内置。写错名字构建报 `SKIN_UNKNOWN` 并给出最接近的候选。

## 七、媒体

v0.9.0 起媒体由 `engine/tools/gen_media.py` 统一生成（依赖 pillow：`pip install pillow`；生成结果入库，构建本身不依赖本工具）：

```bash
cd engine
python tools/gen_media.py --site clients/kestrel          # 缺什么补什么
python tools/gen_media.py --site clients/leafworks --force # 全部重生成
python tools/gen_media.py --site clients/kestrel --list    # 只列出槽位
```

两种槽位，两种来源：

1. **有原图**：写 `media/sources.yaml`（`out` 槽位路径不带扩展名 / `src` 原图 / `focus` 焦点 0–1 / `zoom` 放大倍数 / `cut` 底部裁切比例，默认 0.13 用于切掉生成图水印）。工具裁成 4:3、1600px、JPEG q86。客户给真图后改 `src` 重跑即可，站点路径不变。
2. **没原图**：按主题色板 + 版式生成品牌图案占位图（路径做种子：同路径永远同一张，不同槽位互不相同、同一站视觉语言一致）。

纪律：

1. 引用 **`.jpg`**（v0.9.0 起，占位图与实拍图统一 JPEG——PNG 存渐变会超 `max_kb` 告警线）。引用主体不要写 webp。
2. 单图 **<400KB**（`settings.yaml` 的 `images.max_kb`，超限告警）。
3. 文件命名 `kebab-case`，按 `products/ certs/ team/ factory/ cases/` 分目录。
4. 证书 PDF 与 logo SVG 是一次性资产，直接改文件即可，不走本工具。

## 八、询盘

### 8.1 配置（`settings.yaml`）

```yaml
inquiry:
  recipients: [sales@example.com]
  required: [name, email, message]
  success_url: /{lang}/thank-you/
  rate_limit_per_hour: 10     # 单 IP 每小时（默认 10）
  rate_limit_per_day: 30      # 单 IP 每 24 小时（默认 30）
  # webhook: https://qyapi.weixin.qq.com/...
```

**表单字段**（0.11.0）——默认 `fields: [name, company, email, country, product, volume, message]`，可在 settings.yaml 里裁剪：

| 键 | 控件 | 说明 |
| --- | --- | --- |
| `name` / `company` / `email` / `phone` | 文本 | `phone` 选填 |
| `country` | 下拉 | 引擎内置国家表（geo 包），入库存 ISO 两位码 |
| `product` | 下拉 | 自动列已发布产品；产品详情页询价时自动变为隐藏字段 |
| `volume` | 下拉 | **年采购量估算**，档位按 40 尺柜计数（试单 / <1 柜 / 1–5 / 5–20 / 20+ / 年度合同）——柜量是所有外贸品类通用单位。B1 A4 要求的四项（国家/年采购量/目标市场/用途）由字段 + 留言框共同覆盖 |
| `message` | 文本域 | 必填 |

必填默认只有 3 项（name/email/message）——每多一个必填项转化率掉一点，字段可以多，必填不能多。

**联系浮层与页脚**（0.11.0）——由 `settings.yaml` 的 `contact:`（email/phone/whatsapp）、`company.address`、`social:` 驱动：配了就输出（浮层三条直达按钮 + 页脚三列：品牌地址/联系直达/法律页），不配就不输出。隐私政策与贸易条款页 `engine new` 自带起草版，把方括号占位替换成真实信息即可；页脚只链接**已发布**的这两页。

**分享、收录与下载**（0.12.0）——都不需要额外配置：

- **分享卡**：`python tools/gen_media.py --site <站点目录>` 会给每站生成 `media/brand-card.jpg`（1200×630，主题色深底 + 品牌名）。没有 cover 的页面 `og:image` 自动用它兜底；有 og:image 的页面输出 `twitter:card=summary_large_image`。
- **GA4 与收录**：`analytics.ga4_id` 填了即启用（Cookie 同意后才加载）；致谢页自动发 `generate_lead` 转化事件。`analytics.gsc_verify` 填 Search Console 验证码即输出验证 meta。
- **结构化数据**：BreadcrumbList / FAQPage / Organization（含 logo、sameAs）全部自动生成，无需配置。
- **移动导航**：≤900px 自动折叠为汉堡（零 JS），无需配置。
- **目录下载**：放好 PDF 后在 settings.yaml 配 `catalog: {file: media/catalog.pdf, label: {en: ..., zh: ...}}`，页脚出现下载入口；链接加 `?intent=catalog` 指向联系页可预填留言。单个产品的规格书用产品 yaml 的 `datasheet:` 字段（指向站内 PDF）。两处 PDF 缺文件时 `gen_media.py` 会生成占位版，替换真文件即可。

**收件与 SMTP 走环境变量，绝不写进 settings.yaml**（会进 Git）：

```bash
export ENGINE_SMTP_HOST=smtp.example.com
export ENGINE_SMTP_PORT=587
export ENGINE_SMTP_USER=robot@example.com
export ENGINE_SMTP_PASS='******'
export ENGINE_MAIL_FROM='Leafworks <robot@example.com>'
export ENGINE_TURNSTILE_SECRET=...      # 可选，缺失时跳过第 4 层反垃圾
```

### 8.2 运营

```bash
engine inquiries                 # 列表
engine inquiries --json          # 机读
engine digest                    # 手动发未读汇总
engine digest --cron             # 常驻，每日 09:00 发
```

**通知链路的三条前置**——漏一条就会出现「询盘进了库，但没人知道」：

1. **发件域必须配 SPF + DKIM + DMARC**。这一步在引擎之外，但它是「询盘通知进垃圾箱」的头号原因，而且完全静默：数据库有记录、后台能看到，只是没人收到信。交付时把这三条 DNS 记录当成上线清单的一项。
2. **通知正文必须带齐四样**：客户信息 + **来源页** + **UTM** + 提交语言与时间（按客户时区换算）。少了来源信息，后面所有渠道归因都做不了——询盘是自然搜索来的还是某封开发信来的，事后无法补。
3. **三通道互补，不是三选一**：邮件（主，可留档）→ webhook（快，企业微信 / Slack 机器人，12 小时内响应是 B 端成交第一杠杆）→ `digest`（兜底，防漏看）。

### 8.3 反垃圾与数据

五层：蜜罐 → 时间戳（<3s 判机器人）→ 限流（IP 10/h **且** 30/24h，两道闸都在同一把 IP 锁内复查）→ Turnstile → 内容启发式。**误判不删，只标 `spam_score`。**

询盘落 SQLite（`.data/inquiries.db`），`ip_hash` 加盐不存明文 IP。盐在 `.data/ip_salt`（32 字节，权限 0600，首次启动自动生成）：

- **部署/迁移时必须连 `.data/ip_salt` 一起带走**。丢了它，历史 `ip_hash` 全部对不上——限流计数当场归零，等于给刷单的人重新发牌。备份也一并复制这两个文件。
- 也别把它提交进 Git（`.data/` 默认 gitignore）。

### 8.4 容量、压测与自己动手测

**实测天花板约 600 次/秒**（SQLite 单写者 + 每次 INSERT fsync），而成熟 B2B 外贸站的询盘速率是 **0.2 次/秒**——余量约三千倍。**容量不是问题，防护才是**：单 IP 被「10/h + 30/24h」挡住，但 1000 个 IP 各发一条就能打满。分布式刷单要在 Cloudflare 层做速率限制与 Bot 管理，别指望应用层硬扛。

需要更高吞吐时（展会后集中爆发、或客户把表单当 API 用），**改 `settings.yaml` 一行即可**（`serve` 没有 `--db` 参数，DSN 是站点配置）：

```yaml
store:
  driver: sqlite
  dsn: "file:/srv/sites/layanshi/.data/inquiries.db?_pragma=synchronous(NORMAL)"
```

同负载下 601 → 1479 rps、p99 1122 → 289 ms。**但代价是操作系统崩溃/断电时可能丢最近若干条**——询盘是客户真金白银的购买意向，默认 `FULL` 不提供开关，就是这个原因。

> 两点容易踩：① 以 `file:` 开头的 DSN **原样透传**，不做站点目录解析，所以里面要写**绝对路径**；普通路径（`.data/inquiries.db`）才是相对站点根的。② 这个参数是**每站**的，改完要重启 `serve`。

**自己压一遍**（工具在 `engine/tools/loadtest`）：

```bash
# 1) 构建（两个二进制都落在 engine 根目录）
go build -o engine.exe ./cmd/engine
go build -o loadtest.exe ./tools/loadtest

# 2) 起服务，另开一个终端。--trust-proxy 才能用 X-Forwarded-For 模拟不同 IP
cd examples/zentea && ../../engine.exe serve --addr 127.0.0.1:18090 --trust-proxy

# 3) 回到 engine 根目录，100 并发 / 100 个不同 IP
./loadtest.exe -mode distinct -n 100 -c 100 -db examples/zentea/.data/inquiries.db

# 4) 100 并发 / 同一 IP：放行数必须精确等于 rate_limit_per_hour
./loadtest.exe -mode sameip -n 100 -c 100 -db examples/zentea/.data/inquiries.db
```

参数：`-url`（站点根地址，默认 `http://127.0.0.1:18090`，与上面的 `--addr` 对齐）、`-n` 总数、`-c` 并发、`-mode distinct|sameip`、`-db`（回库核对，路径给错就核不出东西）、`-out report.json`、`-tag` 批次标识。**退出码 0 = 全部核对通过，1 = 有丢单/重复/内容不一致**，可直接进 CI。

它比对的不只是状态码，而是「返回 201 的每一条是否真的在库里、字段是否逐字节相同」——所以它能发现「每条都落库了，但落库数量超过限流阈值」这类**状态码全绿却逻辑错误**的问题。

> ⚠️ **只跑一个实例**。限流锁是进程内的：起两个 `engine serve`，同一 IP 会在两个进程各放行一份。多实例必须把「复查+插入」下沉成数据库原子操作（`INSERT ... SELECT WHERE (SELECT COUNT(*) ...) < N`），不是加分布式锁。DB 也只有单写者，多实例写同一个文件会互相等锁。

### 8.5 页面字节预算与机器可读产物（0.13.0）

构建结束时会算一次**页面字节预算**，并写进 `report.json`：

```json
"budget": { "budget_kb": 1024, "worst_url": "/en/products/mountain/m720-trail/index.html", "worst_kb": 38, "over": 0 }
```

- 统计口径：**HTML 全文 + 首屏 CSS（内联与样式表）**，不含图片（图片走 `<img>` 懒加载与内容哈希，另有超限告警兜）。
- 单页超 1 MB 报 **`PAGE_BUDGET_EXCEEDED`（警告）**，并把最差页面打印出来。弱网（非洲/南亚的 3G）下，1 MB 的 HTML 已经要 8 秒以上。
- 门限写死在代码里（`pageBudgetBytes = 1024*1024`），**不做配置项**：这不是客户偏好，是工程质量线。ridgeway 实测最差 38 KB，离红线很远。

同一批构建还会产出四个**机器可读文件**（无需配置，有内容就有）：

| 产物 | 路径 | 谁会用 |
|---|---|---|
| `llms.txt` | `/llms.txt` | AI 搜索 / 采购助手：实体信息 + 产品（型号·MOQ·交期·HS）+ 页面清单 |
| 参数 CSV | `/{lang}/products/{cat}/{slug}/specs.csv` | 采购：`Group,Label,Value` 可直接透视或做比价表 |
| SKU 清单 | `/data/sku-list.csv` | 采购：发 RFQ 的底表（只含已发布产品） |
| 产品图包 | `/data/product-images.zip` | 「先发几张图看看」——封面图打包 + README |

页脚会自动出现「Data」出口。**图包链接只在真的有封面文件时才渲染**——没图就不给链接，避免死链（E5 比「少一个下载」严重得多）。

## 九、两个后台怎么选

| 你的身份 | 用哪个 | 一句话 |
| --- | --- | --- |
| 交付期开发者（改结构、调 SEO、批量改字段） | `engine admin` | 改**文件**，保存即重建，强制 `127.0.0.1` |
| 交付后客户（改价格、上新品、改文案） | `engine studio` | 改**内容库**，表单 + 审核流，`export` 才回文件 |

⚠️ **两条链路互不相通**：admin 不写库，studio 不写文件。**不要让客户在两边同时改同一个产品。**

studio 首次启动会引导创建 admin 账号并打印一次性口令；编辑提交后进 `in_review`，admin 发布才对前台生效（`/preview/` 可先看效果）。

## 十、上线

| 路线 | 命令 | 适用 |
| --- | --- | --- |
| VPS | `rsync -a --delete .build/public/ user@host:/srv/www/site/` + nginx + systemd | 要跑询盘 API |
| Cloudflare Pages | `wrangler pages deploy .build/public` | 纯静态（询盘需另行部署 API） |
| GitHub Pages | 用 `examples/deploy-pages.yml` | 展示站、无询盘 |

`engine deploy --to <dir>` 做三件事：sha256 比对（幂等，第二次 0 copied）、**孤儿清理**（下架页必须从线上消失）、可选 `--manifest` 写清单供 CDN 预热。

**nginx 关键两行**：哈希媒体 `immutable` 长缓存；`/api/` 反代 `engine serve`。

## 十一、排错手册

### 11.1 构建类

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| `yaml: unmarshal errors` 指向某行 | plain scalar 含 `": "`，或引号不配对 | 改破折号 / 整值加引号 |
| 文案莫名短了一截，零报错 | i18n 写成流式映射被截断 | 改块式；`I18N_UNKNOWN_KEY` 会提示 |
| 整站配色变成默认绿 | theme.yaml 解析失败曾静默回退 | v0.8 起会报错；检查 fonts 引号 |
| 图片成片不加载，控制台无错 | `srcset` 里有 `0w` | 引用 PNG 原图，同名 webp 交给引擎 |
| 某区块整块不见了 | 区块 `type` 拼错 | 看构建报错的白名单列表 |
| `MEDIA_NOT_FOUND` | 路径写错或文件未放 | 从 `media/` 起写相对路径 |
| `CERT_EXPIRING` 警告 | 证书 90 天内到期 | 换新证或更正日期 |
| `SEO_TITLE_LONG` | 标题 >60 字符 | 缩短，别靠截断 |
| `THEME_UNKNOWN_TOKEN` | 主题色/字体键拼错（最常见：`primary_fill`） | 改成 `primary-fill`；色键白名单见第六节 |
| `SKIN_UNKNOWN` | `skin`（或旧键 `layout`）写了不存在的皮肤 | `engine skins` 查可用名；报错里已附最接近的候选 |

### 11.2 运行类

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| `serve site --addr :9000` 端口没变 | flag 包遇位置参数即停（历史缺陷） | 已修（reorderFlags）；升级版本 |
| 询盘提交 400 | 消息过短 / 字段格式 / 触犯内容启发式 | 看响应 `error` 字段 |
| 询盘 429 `rate_limited` | 该 IP 触达 10/h 或 30/24h | 看响应头 `Retry-After`；若**所有人**都在第 11 条被拦，是反代后漏了 `--trust-proxy` |
| 询盘入库但没收到邮件 | SMTP 未配或配置不全 | 查 `ENGINE_SMTP_*`；`engine digest` 可补发 |
| Windows 终端询盘中文乱码 | 控制台非 UTF-8 | 已内置 `SetConsoleOutputCP(65001)`；升级版本 |
| admin 文件树空白 | 历史前端字段大小写缺陷 | 升级到 ≥v0.8.0 |
| studio 页面从某字段截断 | 模板渲染错误被吞 | 升级到 ≥v0.7.0（已加渲染守卫） |

### 11.3 交付前必跑

```bash
engine validate            # 必须 0 错 0 警
engine build
engine serve -addr :8093
# 然后按 B2 的 Veto 9 条 + Lighthouse 四项 ≥95 + Playwright 390px 截图（B1 v2.0 口径）
```
